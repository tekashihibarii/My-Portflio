Course Reflection: What I Learned in AI Literacy and Responsible Use

Mapúa asCEnd Learning Micro-Credential | Student Reflection Paper

Before taking this course, it was easy to think of tools like ChatGPT as search engines with a personality, or some kind of artificial brain that actually understands what you ask it. The biggest technical thing I learned right away is that generative AI doesn’t “know” anything; it’s a probability engine. It scans patterns in massive amounts of training data and predicts whatever token or word makes the most statistical sense next. Seeing it explained plainly stripped away the magic. When an AI generates a snippet of Python or SQL, it isn’t reasoning through database design or logic—it’s just assembling text based on what other developers have written online. That simple distinction completely changed how I look at the screen. You stop viewing the response as an authoritative answer and start treating it like raw, unverified output that needs inspection.

The course also broke down what actually makes prompting work. Most of us start out by typing one sentence into a prompt box, like “write an authentication script,” and then get frustrated when the code doesn’t work or misses half the requirements. What I picked up is that prompting is more like writing an informal specification. You have to give the model context: what framework you’re on, what libraries you’re using, what inputs it should expect, and what constraints it has to follow. More importantly, it taught the value of iteration. If the output isn’t right, you don’t just scrap it and re-roll the prompt hoping for better luck; you feed the errors back in, point out where the logic broke, and guide it step by step. Treating it like an interactive tool rather than an oracle made my workflow a lot cleaner.

Another major lesson was learning not to trust confident answers. Generative models will sound 100% sure of themselves even when they are completely making things up—whether that’s inventing a non-existent function in a PHP library, citing a fake article, or generating SQL that has subtle syntax errors. In class, it’s tempting to copy code the second it compiles without checking whether it handles edge cases or introduces security vulnerabilities. The course hammered home that linguistic fluency isn’t the same as correctness. Now, whenever an AI suggests a solution, my first instinct isn’t to paste it into my project; it's to open the official documentation or test the function with edge cases to see if it actually behaves the way it claims. The time you save generating code means nothing if you spend three hours tracking down a bug the AI silently introduced.

The privacy and data governance module was probably the most eye-opening part for anyone working in tech. A lot of students don't think twice about pasting entire files into a chat window—including real database schemas, API keys, student credentials, or private configuration files. The course made it clear that public consumer models often store prompt histories and can use that data for future training. Once confidential data leaves your computer, you have no control over whose eyes or server logs it ends up in. Learning this made me rethink my habits immediately. If I’m using AI to help troubleshoot a tricky query or review an algorithm, I now make sure to strip out all real table names, replace passwords with dummy strings, and sanitize the data before hitting enter.

The final and most important takeaway from the course is that accountability always stays with the human behind the keyboard. You can’t turn in an assignment or deploy code to a server and

blame the AI when something fails or causes a security breach. Nobody cares that a prompt generated the error; they care that you didn’t catch it. The course helped me realize that using AI isn’t an all-or-nothing choice. It isn't about banning it completely or letting it do all your thinking for you. It's about knowing when to use it as a brainstorming tool, when to write things from scratch, and always being ready to explain and defend every line of work you submit under your own name.

Becoming a Professional IT Practitioner

To me, being professional in IT is pretty simple at its core: it’s about doing the right thing when you’re working with technology, even when no one is watching. In our BSIT classes, we focus a lot on coding, database queries, and networking, but this lecture made me realize that technical knowledge is only half the battle. We aren’t just playing with tools; we handle real people’s personal data, business records, and critical networks. If an IT person is careless or unethical, it doesn’t just mean a broken program; it can lead to a massive data breach, privacy violations, or system failures that ruin an organization’s reputation and destroy public trust. That’s why technical skills alone aren’t enough. You can be the fastest developer in the room, but if you can’t be trusted with confidential data or if you’re unreliable and dishonest, you aren’t a true IT professional.

Looking at the characteristics of an IT practitioner, I think my strongest quality is responsibility, which maps directly to the first of the 5 R’s. When I work on group projects, I take ownership of my work, make sure I meet my deadlines, and never try to hide my mistakes. If a script I wrote breaks a system, I believe in admitting it and fixing it instead of blaming others or pretending it wasn’t me. On the flip side, the area where I have the most room to grow is readiness to learn. It is easy to get comfortable just doing the homework assignments and stopping there. But because technology changes so fast, we have to be lifelong learners. I want to build a habit of reading technical documentation on my own instead of waiting for an instructor to explain everything. In the future, I want to learn more about cloud database administration and modern cybersecurity frameworks. Keeping up with these fields will require me to attend seminars, earn certifications, and work on personal projects even after I graduate.

As IT professionals, we often get administrative access to sensitive resources like passwords, student records, and company files. Protecting this confidentiality is a major ethical duty because privacy is a matter of respect and trust. Just because you have the technical ability to view someone’s files doesn’t mean you have the right to do so. For instance, if I noticed a coworker had written their password on a sticky note next to their computer screen, I wouldn’t ignore it or use it to poke around. A professional response is to privately and politely point it out to them. I would say, “Hey, I noticed your password is visible right here. It’s a pretty big security risk, so you might want to memorize it or use a secure password manager.” This protects both their personal accounts and the security of the whole organization without causing unnecessary drama or embarrassment.

Our day-to-day conduct, both offline and online, defines our professional reputation. In school or during a future internship, showing professionalism means arriving on time, working well with classmates, and documenting code properly so the next person can maintain it. It also shows in how we talk to users. Instead of being patronizing and saying “your system is broken because you don’t know how to use it,” a professional communicator is patient and says, “The system appears to have encountered an error. Let me check the configuration and help you resolve it.” Digital professionalism is just as important. My social media posts, comments, and online behavior represent me as a future practitioner. What I post online stays there, and employers do look at social media. I need to make sure my digital presence is respectful and doesn’t showcase unprofessional behaviors or unauthorized school data.

As a future IT professional, I commit myself to taking full ownership of my mistakes and correcting them honestly, safeguarding the privacy of any user data or systems I am entrusted with, and maintaining an active readiness to learn by continuously upgrading my skills outside the classroom. By practicing these principles in my daily studies and group projects, I hope to build a reputation as a reliable and ethical IT practitioner before I even graduate.

Building Your IT Career: Opportunities in Cloud Computing and Microsoft Credentials

Seminar Reflection Paper | Guest Speaker: Ms. Mizel Narag

Attending the seminar “Building Your IT Career: Opportunities in Cloud Computing and Microsoft Credentials” with Ms. Mizel Narag was a much-needed reality check for me as a BSIT student. When you are busy keeping up with daily coursework, it is easy to assume that simply earning your diploma will be enough to land a good job. The most important lesson I took away from Ms. Narag’s talk is that a degree is really just the starting point. The IT industry changes too quickly for anyone to rely solely on classroom theory, and employers are looking for graduates who take the initiative to learn industry-standard tools on their own.

Before this session, my understanding of cloud computing was pretty surface-level. I knew companies used it for storage and hosting, but I didn’t realize how completely it dominates modern IT infrastructure. Listening to the talk opened my eyes to the fact that cloud computing isn’t just one single job; it is a massive field with opportunities in security, networking, data management, and software development. Knowing that companies are actively struggling to find people who understand cloud platforms makes the future feel a lot less intimidating, provided I put in the work now.

This is where Microsoft certifications come into play. One of the hardest parts about being a fresh graduate is the classic catch-22: you need experience to get a job, but you need a job to get experience. Ms. Narag showed us that earning Microsoft credentials is one of the best ways around this problem. Because Microsoft’s ecosystem, from Azure to Microsoft 365, is used by businesses all over the world, having an official certification proves to hiring managers that you actually know how to use their tools. It gives you a clear advantage over other applicants who only have a resume listing their college subjects.

Inspired by the seminar, I want to focus on developing practical skills in Microsoft Azure. Specifically, I want to start with the basics: learning how to deploy virtual machines, manage cloud storage, and understand basic cloud security protocols, with the goal of passing the Azure Fundamentals (AZ-900) exam. To apply what I learned from Ms. Narag, I plan to stop treating my education as something that only happens inside the classroom. I am going to start using free modules on Microsoft Learn this semester and try to incorporate cloud hosting into our upcoming school projects so I have real work to put into my e-portfolio.

Finally, the seminar made me think hard about whether it is smart to apply directly to a massive company like Microsoft right after graduation. Based on the insights shared, I think applying directly for their entry-level or graduate programs is worth a shot if you have done the extra work to stand out. However, for the average graduate, it is probably more practical to start at a smaller local IT company or a Microsoft partner organization first. Working at a smaller firm lets you wear different hats, make mistakes, and get your hands dirty with real-world troubleshooting before stepping into a high-pressure corporate giant. If I do decide to aim straight for Microsoft, I know my transcript won’t be enough. I will need a solid portfolio of working projects, at least one foundational

Microsoft certification under my belt, strong communication skills, and the confidence to prove that I am ready to keep learning from day one.
